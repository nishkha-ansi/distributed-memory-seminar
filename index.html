01 · What Is Distributed-Memory Parallel Programming?

Distributed-memory parallel programming divides a large task among separate processes or computers. Each process has its own private memory. Processes communicate by sending and receiving messages.

🧩

Step 1: Divide the Task

A large problem is split into smaller tasks that can be handled separately.

⚙️

Step 2: Process the Data

Each worker handles its own piece of data using its own memory.

📨

Step 3: Exchange Results

Workers send their results to another process or to a coordinator.

Easy example: A teacher divides 300 papers among six helpers. Each helper checks a group. At the end, all marks are collected. The helpers represent workers in a parallel program.

02 · Shared Memory vs Distributed Memory

The key difference is how each worker accesses data.

🧠

Shared Memory

Threads can access the same memory area. If two threads change the same data, synchronisation may be needed.

Example: Threads update a shared counter.

🌐

Distributed Memory

Each process has its own memory. Processes exchange information through messages rather than directly accessing another process's memory.

Example: Computers calculate different parts of a weather model.

📨

Message Passing

Processes send and receive data to coordinate their work and share results.

Scalability

A parallel system can use more workers to tackle larger tasks, although communication has a cost.

03 · Parallel Programming Patterns

Patterns are common ways to organise parallel work.

✂️

Divide and Conquer

Split a large problem into smaller problems, solve them, and combine the answers.

🏭

Work Pool

A coordinator assigns tasks to workers that are ready to process them.

🚦

Pipeline

Data moves through several stages, like a production line.

📦

Data Decomposition

Split input data into chunks and perform similar work on each chunk.

🛠️

Functional Decomposition

Different workers perform different functions or stages of a task.

🔁

Phased Computation

Workers complete a phase, exchange information, and continue to the next phase.

04 · Real-Life Applications

Parallel computing helps solve problems that require a lot of computation.

🌦️

Weather Forecasting

Different processors calculate conditions for different regions of a weather model.

🎬

Movie Rendering

Different frames or image sections can be assigned to separate workers.

📊

Big-Data Analysis

Large datasets can be split into chunks, analysed, and combined.

05 · Race Conditions and Synchronisation

A race condition happens when the result depends on the timing or order of tasks accessing shared data.

⚠️

Race Condition

Two tasks may read the same old value and overwrite each other's update.

🔐

Lock

A lock controls access to a critical section so only one thread at a time can enter.

🚦

Semaphore

A semaphore controls how many tasks can access a resource at the same time.

🔒

RLock

A re-entrant lock allows the same thread to acquire the lock again.

📬

Queue

A queue passes items between tasks in an organised way.

🔔

Event

An event signals that something has happened and another task can respond.

Demo 1 · Split Work Waiting to run 
numbers = [2, 3, 4, 5, 6, 7]
chunks = [numbers[0:2], numbers[2:4], numbers[4:6]]
results = []

print("Main task:", numbers)

for worker, chunk in enumerate(chunks, start=1):
    squares = [n * n for n in chunk]
    print(f"Worker {worker}: {chunk} -> {squares}")
    results.extend(squares)

print("Combined result:", results)
